# PBN0013

*The base-type 'X' is a proto-contract, but does not declare 'Y' as a sub-type.*

protobuf-net serializes an inheritance hierarchy by writing each layer as a nested message, and it
only knows the hierarchy exists if something tells it. A derived type that is never declared as a
sub-type is treated as an **independent contract**: it serializes its own members and *silently
ignores every inherited one*. That is the surprise this warning exists to prevent — nothing fails,
the payload is simply missing half the data.

Bad:

``` csharp
[ProtoContract]
public class Animal
{
    [ProtoMember(1)] public string Name { get; set; }
}

[ProtoContract]
public class Dog : Animal // Name is silently dropped when a Dog is serialized
{
    [ProtoMember(1)] public int Bark { get; set; }
}
```

Good:

``` csharp
[ProtoContract]
[ProtoInclude(100, typeof(Dog))]
public class Animal
{
    [ProtoMember(1)] public string Name { get; set; }
}
```

## When the base type cannot name the sub-type

`[ProtoInclude]` goes *on the base*, so it is no help when the base has never heard of the sub-type —
it lives in a package that does not reference yours, or the sub-type is a generic construction such
as `Tagged<Order>` that no base library could have written down.

For the **compile-time model** used by native AOT — see [aot](../aot) — declare the link out-of-band
instead. This satisfies the warning, because it really is a declaration: the generated serializer
treats it exactly as though the base had carried `[ProtoInclude]` all along.

``` csharp
[ProtoModel]
[ProtoSerializable(typeof(Animal))]
[ProtoSubType(typeof(Animal), typeof(Tagged<Order>), 100)]
public partial class MyModel : TypeModel { }
```

It can also be declared on an **assembly** or a **module**, which is how a package ships the linkage
for a hierarchy it extends; all three sites satisfy this warning.

## When you register sub-types at run time

`RuntimeTypeModel` builds its model at run time, so the hierarchy may be declared in code the
analyzer cannot see:

``` csharp
RuntimeTypeModel.Default[typeof(Animal)]
    .AddSubType(100, typeof(Dog));
```

That is a perfectly good way to use protobuf-net, and nothing static can confirm it happens — so
**this warning is expected in that case and can be ignored**. Suppress it where you declare the
sub-type, or project-wide in `.editorconfig`:

``` ini
dotnet_diagnostic.PBN0013.severity = none
```

Note that `[ProtoSubType]` is read by the source generator only: it does **not** register anything
with `RuntimeTypeModel`. If you use both models, keep calling `AddSubType` for the runtime one.

## When the sub-types are deliberately unknown

If a base type is meant to be extended by types it will never know about, and you accept that only
its own members go on the wire, say so on the contract — which turns off both this warning and
`PBN0014`:

``` csharp
[ProtoContract(IgnoreUnknownSubTypes = true)]
public class Animal { }
```
