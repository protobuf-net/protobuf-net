# PBN0030

*'X' is non-nullable, but SkipConstructor means no constructor or initializer runs on deserialize;
it is null whenever the payload does not carry it.* For a member that is not serialized at all, the
message says it is null after every deserialize.

This is the rule for members that are not collections; [PBN0028](PBN0028) covers collections.
`[ProtoContract(SkipConstructor = true)]` creates the instance without running **any** constructor,
and that includes initializers, which the C# compiler places inside the constructor. A struct contract
is the same with or without the option: protobuf-net reads into `default(T)`. So `= ""` and `= new()`
never run on deserialize, and the member starts out `null`:

``` csharp
#nullable enable
[ProtoContract(SkipConstructor = true)]
public class Order
{
    [ProtoMember(1)] public string Customer { get; set; } = ""; // reported
    private readonly object _sync = new();                       // reported: always null
}
```

**A member that is not serialized is null after every deserialize.** A lock object, a cache or a
logger then fails on first use, far from the contract.

**A serialized member is null whenever the payload does not carry it.** A non-null string or message
*is* written, even when empty, so between two protobuf-net endpoints on the same schema it comes back.
The payload lacks it when:

- it was written before the member was added;
- the sender does not write an empty string. Other proto3 implementations leave `""` out, and so does
  protobuf-net for a member with `[DefaultValue("")]`, which is what protogen generates for proto3.

It is the setting on the **concrete type being read** that counts: on an abstract type it does
nothing, and on a sub-type it strips the members that type inherits as well. So a base's members are
reported when any sub-type its `[ProtoInclude]`s reach sets it.

A positional record under `SkipConstructor` is the common case, since that is how a record without a
parameterless constructor is deserialized. Every non-nullable string or class parameter is reported:

``` csharp
[ProtoContract(SkipConstructor = true)]
public record Person([property: ProtoMember(1)] string Name); // reported
```

## Fixes

**Declare it nullable.** The lightbulb offers this. The value really can be null, and saying so
makes the compiler ask every reader to deal with it.

**Restore it in a deserialization callback.** protobuf-net runs these on the new instance even when
no constructor ran:

``` csharp
[ProtoAfterDeserialization]
public void OnDeserialized() => Customer ??= "";
```

Make it `public`, and note that in an inheritance hierarchy only the root's callbacks run, as
described under [PBN0028](PBN0028). A callback is an ordinary method, so it cannot assign a
`readonly` field, a getter-only property or an `init`-only one — a positional record's parameter is
one — and the message does not offer it for those. There, declare it nullable, or make it settable.

**Drop `SkipConstructor`**, if the type has a parameterless constructor. Its initializers then run.

## What is not reported

- **Types constructed normally.** Their initializers run. A member with no initializer
  (`required string Name`, `= null!`) is null only when the field is absent, and the compiler's
  CS8618 has already said so; reporting every such DTO member would drown everything else.
  Collections are the exception, because an empty one is never written; that is [PBN0028](PBN0028).
- Collections, which are PBN0028's; nullable members; value types; and code without nullable
  annotations enabled.
- `SkipConstructor` on an abstract type, where it has no effect — unless a sub-type sets it too. A
  sub-type added at run time with `AddSubType` is invisible to an analyzer.
- Surrogated types, types with a hand-written `Serializer`, and types protobuf-net treats as a
  collection, whose members it never reads.
- Members that a deserialization callback assigns.

## Turning it off

``` ini
[*.cs]
dotnet_diagnostic.PBN0030.severity = none
```
