# PBN0027

*'X' is a non-nullable collection, but SkipConstructor means no constructor or initializer runs on
deserialize, so it is null whenever the payload does not carry it.*

`[ProtoContract(SkipConstructor = true)]` creates the instance without running any constructor, so
every field starts out `null` — and that includes field and property **initializers**, which the
C# compiler places inside the constructor. A collection member is only assigned when the payload
actually carries it, and an **empty collection is normally not written at all**: protobuf has no way
to say "present, but empty". So a sender holding `[]` leaves the receiver holding `null`.

Nothing warns about this. The member is declared non-nullable, so the compiler is satisfied that
reading it is safe, and the `NullReferenceException` turns up later, somewhere far from the contract,
and only for the messages that happened to have no elements.

Bad:

``` csharp
#nullable enable
[ProtoContract(SkipConstructor = true)]
public class Order
{
    // the initializer never runs on deserialize: an order with no lines comes back with null here
    [ProtoMember(1)] public List<OrderLine> Lines { get; set; } = new();
}

[ProtoContract(SkipConstructor = true)]
public record Tags([property: ProtoMember(1)] string[] Values);
```

It is sharper still when the member is not part of the contract at all. Nothing ever writes it, so
it is `null` after **every** deserialize:

``` csharp
#nullable enable
[ProtoContract(SkipConstructor = true)]
public record TestRecord(string[] Array); // no [ProtoMember]: Array is always null
```

## Fixes

Declare the member nullable. The value really can be null, and saying so makes the compiler ask
every reader to deal with it:

``` csharp
[ProtoMember(1)] public List<OrderLine>? Lines { get; set; }
```

Or restore it in a deserialization callback, which protobuf-net does run on the uninitialized
instance. Any of `[ProtoBeforeDeserialization]`, `[ProtoAfterDeserialization]`, `[OnDeserializing]`
and `[OnDeserialized]` satisfies this warning, provided it assigns the member:

``` csharp
[ProtoContract(SkipConstructor = true)]
public class Order
{
    [ProtoMember(1)] public List<OrderLine> Lines { get; set; } = new();

    [ProtoAfterDeserialization]
    private void OnDeserialized() => Lines ??= new();
}
```

Or, if nothing forces it, drop `SkipConstructor`: without it the constructor runs and the
initializer does its job. It is usually there because the type has no parameterless constructor.

## What is not reported

- **Nullable members** (`List<T>?`), and members in code without nullable reference types enabled —
  those have promised nothing.
- **Value types**, including `ImmutableArray<T>`. Note that a default `ImmutableArray<T>` throws on
  most uses too; it is not reported only because nullable annotations cannot describe it.
- `byte[]` and the other "bytes" types. They are a single scalar to protobuf-net rather than a
  collection, and a non-null one — even an empty one — is always written.
- **Abstract types** and **surrogated types**. `SkipConstructor` applies to the type that is actually
  constructed, so on an abstract base it has no effect; with a surrogate, protobuf-net constructs the
  surrogate instead.

## A note on packed scalars

By default protobuf-net writes a zero-length header for an empty `[ProtoMember(IsPacked = true)]`
collection of scalars, so such a member does survive a round-trip between two protobuf-net
endpoints. That is kept only for compatibility with protobuf-net v2: it is switched off by
`RuntimeTypeModel.SkipZeroLengthPackedArrays`, and other protobuf implementations do not write it,
so do not rely on it. The member is reported like any other.
